# Mass-Balance & Yield auditor

The third auditor checks e-waste, battery, tyre and used-oil recyclers whose input-tonnage certificates exceed the support in sold products, electricity bills and plant capacity. It emits ranked inspection cases with quantitative reasons, real row references, a separate screening queue and a suspected-hollow-tonnes estimate. The entire implementation lives in `yieldbal/`; the existing agents, root README, requirements and generator are unchanged.

**All data is synthetic.** The detector was designed knowing the planted fraud mechanisms. Yields, kWh/t, solar credit, capacity utilisation and tariff references are modelling assumptions; replace them with validated plant-specific and regulatory references before use with real observations. Scores are inspection ranks, not fraud probabilities. Suspected hollow tonnes are an estimate under observable ceilings, not measured or verified fraud.

## Run locally

From the repository root, install `yieldbal/requirements.txt` into an isolated Python environment (Python 3.12 tested), then:

```bash
python -m yieldbal.run_eval --data data/synthetic --out yieldbal/outputs/seed42
python -m streamlit run yieldbal/app.py --server.address 127.0.0.1 -- --run yieldbal/outputs/seed42 --data data/synthetic
python -m pytest yieldbal/tests -q
python -m yieldbal.config_demo
python -m yieldbal.verify_dashboards --siblings
```

`run_eval` exits 1 when a statistical acceptance criterion fails, after saving working scores and the complete report. This is deliberate: failed research criteria are not hidden as successful tests. `pipeline` creates scores without reading labels. Committed results include scores, signals, model contributions, run metadata and metrics. Monthly checks and intermediate features are regenerated by the pipeline, or the dashboard rebuilds monthly evidence from observable data when the monthly file is absent.

Held-out data can be reproduced without changing the seed-42 world:

```bash
python -m synthdata.generate_all --scale large --seed 7 --only registry,yield --out data/synthetic_seed7_yield
python -m yieldbal.run_eval --data data/synthetic_seed7_yield --out yieldbal/outputs/seed7
python -m streamlit run yieldbal/app.py --server.address 127.0.0.1 -- --run yieldbal/outputs/seed7 --data data/synthetic_seed7_yield
```

## Physical checks and ranking

* Certificates are based on processed input tonnes. Configurations are looked up by `(stream, process_type)`; unsupported bases, missing configs and invalid input quantities fail explicitly.
* Capacity uses declared annual capacity / 12. Connected load uses 730 hours/month at 90% utilisation divided by the configured minimum kWh/t. These remain assumptions, and campaign peaks may require inspector review.
* Grid energy is never set to zero for an absent bill. The lower of reported units and units implied by the energy charge gives a conservative alternative ceiling. Quiet residual energy estimates base load, capped at 20% of median units. Declared solar adds 150 hours/month at 85% conversion. Undeclared solar remains unknown.
* Energy-charge arithmetic is tested against state/FY tariffs with 3% tolerance. A mismatching bill is a document finding; it does not establish which field was altered.
* Output checks compare saleable output with trailing 3- and 6-month input windows. Two subsequent sales months are credited to each window, including a generous allowance for prior inventory. The last two months have incomplete output evidence. Only saleable fractions enter mass support. A logistic-normal composition residual includes missing products; product prices are checked against observed peers without assuming a market-price fraud mechanism.
* Own-baseline changes use the first six active months. Persistent fabrication can contaminate that baseline. Cohort median/MAD and IQR scales, one-sided percentile features, an Isolation Forest and SHAP supply unsupervised residual scores and model attributions. Numeric physical reasons remain the primary explanations.
* The score is a weighted rank average: physical feature ranks 60%, residual ranks 25%, direction-gated forest ranks 15%. Energy/output weights are 2, capacity/bills 1 and auxiliary drift/mix/price 0.5. No thresholds or weights use labels.

**Priority policy:** average deficit of at least 15% in two physical groups, at least 50% in one group, or mean bill discrepancy at least 6% for an entity with three observed months. **Screening policy:** average physical deficit at least 5%, or bill discrepancy at least 3%; it includes priority. A risk score does not itself trigger either queue. The dashboard explicitly separates their precision and coverage.

**What-if:** each monthly claim is bounded by the minimum available energy, connected-load, capacity and output support. The difference is suspected hollow tonnage. The slider proportionally lowers claims while holding evidence fixed, reports the largest share that passes all available tonnage ceilings and separately reports inconsistent bills. Missing energy and censored output windows remain unknown. Lowering claims cannot fix bill arithmetic or auxiliary statistical anomalies.

## Evaluation disclosure

All detector thresholds, weights and physics were fixed before viewing evaluation. Seed-42 and seed-7 output was inspected during development. After evaluation the explanation formatter was corrected to say “unavailable” for missing statistics, stream/state metadata was added to signals, input validation and deployment packaging were hardened, product-specific drill-down evidence was added to the case/tool, and an unadjusted grid-energy baseline was added to the report. These changes do not alter scores or flagging policies; neither seed was used to tune them. Seed 7 was evaluated with the same frozen rules. No post-evaluation threshold lowering or weight selection was performed.

Labels are read only in `evaluate.py`. It reports pooled/per-stream AUC and precision, difficulty tiers, fraud behaviours, monthly localisation, hollow-tonnage recall, confounder false positives, label artefacts and ten ablations. The existing quoted subtle-tier benchmark of 0.84 is retained as an external acceptance target; raw-grid baselines recomputed with this implementation's entity aggregation are also saved, rather than treating that benchmark as a matched experiment.

## Config-only extension

`python -m yieldbal.config_demo` creates a made-up foam-recovery stream with exactly 12 YAML lines, five plants and observable synthetic rows, then runs the unchanged pipeline. There is no stream-specific Python branch. Configurations define energy ranges and product fractions/tolerances; non-saleable products never increase observable output support. This is a configuration demonstration, not a claim that any stream's physical priors have been validated.

## Dashboard and tests

Four tabs provide a stream/state-filtered inspection list with CSV export, a recycler case with monthly claim/support curves and an evidence table, the claim-reduction slider, stream comparison and methodology/results. No labels are loaded by the dashboard. Empty filters, absent run files, missing energy and incomplete output evidence have explicit UI states.

The test suite exercises deterministic scoring, config-only addition, inventory lag, non-saleable/missing products, zero and absent bills, doctored units, solar, invalid and duplicate inputs, what-if boundaries, PDF extraction, low-confidence/ambiguous fields, tool wrappers, template fallback, Lambda filtering/error handling/cache, SAM structure and dashboard reruns. The dashboard verifier also exercises the existing Phantom Plastic and Biomedical dashboards and their selectors without editing their code. The full Biomedical pipeline was rerun on 4,652,377 pickups; stored facility and treatment scores match to floating-point precision. A full 200-epoch Phantom Plastic rerun is part of the regression check. See `outputs/verification.json` for the final test record.

Textract uses `AnalyzeExpense` on a single PDF, checks extraction confidence and handles missing/zero numeric fields separately. Ten synthetic sample bills, including two deliberate edits, round-trip from PDF text into an AnalyzeExpense-shaped offline fixture and the bill-consistency check. This verifies rendering/parsing/checking, **not Textract OCR accuracy**. The PDFs are generated locally and omitted from Git.

Strands tools expose `check_energy_ceiling`, `check_output_balance`, `explain_recycler` and `top_suspects`. `YIELDBAL_BEDROCK_MODEL` or an explicit model id enables Bedrock; no model name is hard-coded. Without that setting, `build_agent` returns deterministic template summaries and the local tools remain usable. SAM packages a small S3-backed Lambda read API at `/top` and `/case/{entity_id}`. Its deployment script prints a plan unless `--deploy` is passed and uploads the already-computed signals after deployment. The SAM bucket blocks public access.

**No AWS deployment or live Textract, Bedrock, Strands planner, S3 or Lambda calls were tested.** Cloud credentials, enabled services, SAM packaging and IAM policies must be verified in the target account. Offline mocks do not establish deployed behaviour.

## Weaknesses

Subtle and output-fabrication fraud remain difficult: a plant can fabricate products and alter electricity documents, and minimum energy ranges leave substantial room for ordinary efficient processing. Sold quantities do not prove physical recovery. Declared solar credit can be too generous; undeclared solar can generate false positives. Campaign processing and stable unusual yields can breach nominal ceilings. Monthly capacity assumes uniform available throughput; permits allowing seasonal peaks need a different reference.

The output-window estimate credits overlapping inventories and is conservative for detection. Its monthly allocation is not a solved stock-flow model, so monthly localisation recall is low and tonnage estimates have substantial absolute error. The last two months lack full lag evidence. Three-month/new plants have limited own-baseline evidence. A first-six-month baseline can already be fraudulent. Product prices carry little information about the generator's fabrication mechanism, and auxiliary scores can weaken the ensemble.

The model is fitted anew on each population, so rank scores are batch-relative and cross-run values are not directly calibrated. This is synthetic mechanism validation with explicitly failed targets, not a production-ready enforcement decision system. Inspectors should corroborate evidence and request original bills, product-sale records, inventory ledgers, capacity authorisations and solar declarations before drawing conclusions.
